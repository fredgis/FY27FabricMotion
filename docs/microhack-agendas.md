# Micro Hack Agendas — Microsoft Fabric Application Motion

**FY27 · Envision your business with Microsoft Fabric · EMEA enablement**

Two complementary **one-day Micro Hacks** that bring the Fabric application motion
to life with partners. Each follows the same rhythm: the **morning** builds shared
understanding through training and live demos; the **afternoon** is a hands-on
**hack** where teams build something real and demo it before the close.

| Micro Hack | For | Approach |
| ---------- | --- | -------- |
| **1 — Business Apps with Microsoft Fabric & Rayfin** | Advisory firms / System Integrators | Spec-driven Business Apps |
| **2 — ISV Workloads with the Fabric Extensibility Kit** | ISVs / SDC | Code-driven workloads that extend Fabric |

### Format at a glance

- **Duration:** one day, 09:00 – 17:30 (≈ 3h30 training & demos in the morning, ≈ 4h hacking in the afternoon).
- **Team size:** 3 – 5 people per team, with a Microsoft coach floating across teams.
- **Outcome:** a working artifact per team plus a clear line back to the motion KPIs.

---

## Micro Hack 1 — Business Apps with Microsoft Fabric & Rayfin

*Advisory / System Integrator track. Teams learn the spec-driven approach to
Business Apps on Fabric and build one end-to-end with Rayfin during the afternoon.*

| | |
| --- | --- |
| **Audience** | Advisory firms & System Integrators (architects, app builders, data consultants). |
| **Approach** | Spec-driven — describe the app, generate it on Fabric with Rayfin. |
| **Objectives** | Understand the Fabric data foundation for Business Apps · Learn the Rayfin spec-driven app lifecycle · Build and extend a working Business App in a half-day hack. |
| **Prerequisites** | Access to a Microsoft Fabric workspace with capacity · A laptop with a modern browser and Entra ID sign-in · Basic familiarity with data models and business processes. |
| **Outcomes & KPI** | A working Business App per team, demoed at the close · Mapped to MSX opportunities (Stage 1 & 2) — vision ACR. |

### Agenda

#### Morning — Training & Demos

| Time | Session | What happens |
| ---- | ------- | ------------ |
| 09:00 – 09:30 | Welcome & motion framing | The motion, the two paths, the Advisory/SI angle and the goals for the day. |
| 09:30 – 10:15 | Fabric foundations for Business Apps | OneLake, workspaces and capacities — the substrate under every Business App. |
| 10:15 – 10:30 | Break | — |
| 10:30 – 11:15 | Introducing Rayfin | Spec-driven Business Apps on Fabric: concepts, the app lifecycle, where the spec fits. |
| 11:15 – 12:00 | Live demo — spec to app | End-to-end: from a written spec to a working Business App, in front of the room. |
| 12:00 – 12:15 | Hack briefing | Scenarios, team formation, success criteria and what "done" looks like. |
| 12:15 – 13:00 | Lunch | — |

#### Afternoon — Hack

| Time | Session | What happens |
| ---- | ------- | ------------ |
| 13:00 – 13:30 | Kick-off & setup | Teams pick a scenario, confirm Fabric workspace access, environment health check. |
| 13:30 – 15:30 | Hack sprint 1 — Build | From data to app: draft the spec, generate the app with Rayfin, get a first version. |
| 15:30 – 15:45 | Break | — |
| 15:45 – 16:45 | Hack sprint 2 — Extend | Polish UX, add security/roles, connect the app to an MSX opportunity scenario. |
| 16:45 – 17:15 | Showcase & peer review | Each team demos for 5 minutes; peers and coaches give feedback. |
| 17:15 – 17:30 | Wrap-up & next steps | Recap, map results to MSX Stage 1 & 2, agree next steps. |

## Micro Hack 2 — ISV Workloads with the Fabric Extensibility Kit

*ISV / SDC track. Teams learn the Fabric extensibility model and build a custom
workload end-to-end with the Fabric Extensibility Kit during the afternoon.*

| | |
| --- | --- |
| **Audience** | ISVs & software development companies (developers, solution architects, product owners). |
| **Approach** | Workload / code-driven — extend the Fabric platform via the Extensibility Kit. |
| **Objectives** | Understand how workloads plug into Fabric · Master the Extensibility Kit dev loop (SDK, manifest, run, publish) · Scaffold, integrate and package a custom workload in a half-day hack. |
| **Prerequisites** | A developer laptop with Node.js and the Fabric Extensibility Kit SDK · Access to a Fabric tenant/workspace with developer mode enabled · Familiarity with TypeScript/React and REST APIs. |
| **Outcomes & KPI** | A custom workload running locally (and publish-ready) per team · Mapped to "workloads per ISV" and Fabric consumption capacity — vision Adoption. |

### Agenda

#### Morning — Training & Demos

| Time | Session | What happens |
| ---- | ------- | ------------ |
| 09:00 – 09:30 | Welcome & motion framing | Why ISVs "become Fabric". The workload-per-ISV goal and the agenda for the day. |
| 09:30 – 10:15 | Fabric platform & extensibility model | How workloads plug into Fabric: the workload hub, item types and integration points. |
| 10:15 – 10:30 | Break | — |
| 10:30 – 11:15 | Fabric Extensibility Kit deep dive | The SDK, workload manifest, frontend/backend, and the local development loop. |
| 11:15 – 12:00 | Live demo — scaffold a workload | Scaffold a workload, run it locally, and publish it to the workload hub. |
| 12:00 – 12:15 | Hack briefing | Scenarios, teams, success criteria for the afternoon. |
| 12:15 – 13:00 | Lunch | — |

#### Afternoon — Hack

| Time | Session | What happens |
| ---- | ------- | ------------ |
| 13:00 – 13:30 | Kick-off & dev setup | Install the SDK, configure tokens, validate the local dev environment per team. |
| 13:30 – 15:30 | Hack sprint 1 — Scaffold & run | Create a custom workload: define item types and artifacts, integrate with OneLake, run locally. |
| 15:30 – 15:45 | Break | — |
| 15:45 – 16:45 | Hack sprint 2 — Integrate & package | Wire up authentication, tie into Fabric consumption capacity, package the workload for publishing. |
| 16:45 – 17:15 | Showcase & peer review | Each team demos its workload; coaches review architecture and readiness. |
| 17:15 – 17:30 | Wrap-up & next steps | Recap, map results to "workloads per ISV" and consumption, agree on the path to publish. |

## Logistics & success criteria

### Roles

- **Lead facilitator:** runs the agenda, keeps time, frames the motion.
- **Technical coaches:** 1 per 2 – 3 teams, unblock during the hack.
- **Product/PM contact:** available for workload questions (Micro Hack 2).

### What participants should bring

- A laptop that can sign in with their Entra ID.
- For Micro Hack 2: local dev tools pre-installed (Node.js + SDK) where possible.

### Environment checklist (prepare before the day)

- Fabric workspace(s) with capacity assigned and access granted.
- Sample datasets and starter specs (Micro Hack 1) / starter repo (Micro Hack 2).
- Developer mode enabled for the Extensibility Kit (Micro Hack 2).

### What "good" looks like at 17:30

- Every team demos a working artifact, however small.
- Each team can name its next step toward an opportunity or a published workload.
- A clear line back to the motion: **ISV + Advisory → ONE Microsoft program.**
